# SKySLICEY72 — oriented branching / open berth

**Status:** runtime research note · no event-schema or admission change  
**Boundary:** Band Runtime owns encounter/admission/refusal/projection/replay behavior. This note does not grant an AI conductor, new authority, or a new canonical event family.

## Why this belongs here

Band Runtime already preserves sovereign channels, append-only encounter history, branch navigation, anticipation-as-proposal, and replay at declared causal cuts.

SKySLICEY72 adds a candidate distinction for creative branching:

```text
branch availability
!=
branch orientation
!=

```

## Y as local branching frame

Use a Y only as a compact model of a three-way local routing frame:

```text
        a
        |
        •
       / \
      b   c
```

Its full orientation grammar has six states:

```text
D3 ≅ S3
|D3| = 6
```

A local frame may therefore distinguish which arm is forward relative to a declared origin and whether the orientation is reflected.

This does not make Y geometry part of the Band Runtime contract.

## Open berth

### `OPEN-BERTH-AS-ORIENTED-SOCKET-001`

A useful creative model is:

> **An open berth is a declared unfilled branch in an already constrained local relation field.**

```text
fixed ancestry
     |
     Y
    / \
known  OPEN
       BERTH
```

The open branch is not arbitrary authority. The existing encounter, disclosure, refusal, and admission boundaries remain in force.

## Suno / generative sibling outputs

A generative encounter may produce sibling candidates:

```text
source S
 -> candidate A
 -> candidate B
```

or more accurately:

```text
S --generation occurrence g--> {A, B}
```

The important provenance is not merely that `A` and `B` resemble `S`. It is that both are attributable outputs of the same bounded generation occurrence when that fact is honestly available.

Later histories may diverge:

```text
S
├─ A -> A'
└─ B -> B'
       
A', B' -> C   (possible later encounter)
```

Do not flatten this to `S -> C` if the intermediate crossings are relevant to the declared projection.

## Handed crossing

A Storyship-like downstream projection may distinguish two histories that have the same endpoint participants but opposite crossing orientation.

Candidate event payload, if ever tested downstream:

```text
orientationRef
crossingSign: +1 | -1
formationRef
parentRefs
```

These are research fields, not runtime additions.

### `RETICULATED-BRAID-001`

```text
same parent set
!=
same parental braid
```

The runtime should continue to preserve enough append-only occurrence history that a richer future projection can distinguish the two when the original encounter actually recorded the distinction.

## Replay rule

At causal cut `t`:

```text
projection(t)
```

may expose only the branch/orientation information that was available by `t`.

Later recognition of a braid pattern may increase relevance; it may not write handedness backward into events that never recorded it.

## Refusals

```text
AI generation != authority
candidate sibling != accepted contribution
same endpoints != same encounter
similar audio != shared generation ancestry
inferred braid != recorded braid
open berth != unrestricted generation
```
