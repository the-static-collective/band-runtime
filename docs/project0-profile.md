# Project0 Conformance Profile — Band Runtime v0.1

This is a downstream product profile. Runtime terms are namespaced payloads and aggregates; they do **not** create Project0 universal node or edge kinds.

| Runtime term | Project0 role |
| --- | --- |
| Formation Trace | attributable source and/or observation payload |
| Participant Channel | downstream aggregate with scope, disclosure, and refusal |
| Clip | existing node kind chosen by epistemic role |
| Historical Surface Ref | addressed sources/edges/receipts plus declared policy |
| Interference Groove | provenance-bearing inference or proposal; never default identity claim |
| Recognition Outcome | observation or rejection plus append-only receipt |
| Reciprocal Influence Receipt | downstream receipt profile |
| Session Projection | disposable, rebuildable projection |
| Mix Artifact | source with complete provenance |

## Non-negotiable constraints

- Retrieval is not authority; similarity is not lineage; confidence is not evidence.
- Rejection remains addressable and cannot become negative training consent.
- An emergent mix never becomes canonical authority.
- Models deposit bounded proposals; deterministic validation admits or rejects them.
- A later recognition affects only projections after its accepted event sequence.
- If implementation needs a new Project0 node kind, stop and record the incompatibility.

## Integration report

Each release must report:

| System | Required status |
| --- | --- |
| Project0 contract/invariants | pinned version + fixture results |
| TranchNode | exact / representable_with_payload / lossy / unavailable / requires_version_boundary |
| Corpus OS | import/export mapping |
| Local extensions | namespace + schema |
| Deviations | explicit, non-silent |

No status may be inferred from similar names alone.
